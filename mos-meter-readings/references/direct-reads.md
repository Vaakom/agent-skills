# Прямое чтение показаний mos.ru

Прямое чтение проверено в авторизованных Chrome и Edge. Используй штатную навигацию по URL в отдельной временной вкладке того же браузера и профиля. Прочитай отображаемый JSON и разбери его в памяти. Для переходов используй только `https://www.mos.ru` и перечисленные ниже маршруты. Браузер сам использует сессию. Не экспортируй cookies, токены, полные URL с параметрами или исходный JSON. Если сессия истекла, пользователь входит вручную. При отказе доступа, HTML вместо JSON, ошибке схемы или неполных данных используй форму портала для соответствующей квартиры.

## Вода

1. Возьми номер квартиры и код плательщика из сохранённой записи в разделе «Код плательщика» штатной формы. `/api/utility-meter/v1/favorites` сообщает только, добавлена ли услуга в избранное.
2. Выполни GET `/api/utility-meter/v1/device` с параметрами `flat` и `payer_code`. Проверяй `code === "SUCCESS"`. Сверь `data.address` с выбранной квартирой. В `data.active` видны `id`, `number`, `model.class`, `model.type`, `inspection_status` и `recent_reading`. Определяй водосчётчики по `model.class === "water"` и виду воды по `model.type`. Если есть относящиеся к запросу неактивные приборы, проверь их отдельно по форме и покажи статус.
3. Для каждого прибора выполни GET `/api/utility-meter/v1/device/{id}/indication/archive` с теми же параметрами. В `data.items` используй `period` для расчётного месяца и `indication` для показания. `null` в строке за нужный месяц означает отсутствие показания. Числовой ноль сохраняй как значение. Сравнивай по месяцам и бери последнее непустое значение до текущего периода.

## Электричество

1. Выполни GET `/pgu2/counters/api/profile` с `info_blocks[]=HOUSE`. В `items` найди запись с `code === "HOUSE"`. Её `data` содержит сохранённые квартиры. Для нужных квартир используй адрес или подпись, `MES_ACCOUNT` и `MES_METER`. Если у квартиры несколько подходящих записей, уточни выбор.
2. Удали из `MES_ACCOUNT` пробелы и дефисы и проверь, что осталось ровно 10 цифр. Раздели строку на 5, 3 и 2 символа без преобразования к числу, чтобы сохранить ведущие нули. Выполни GET `/pgu2/counters/api/mes/checkShetch` с `nm_kng` (первые 5), `nm_abn` (следующие 3), `nn_kr` (последние 2) и `nn_schetch` (`MES_METER`). Из `result` возьми непустые `ID_KNG` и `SCHEMA`. Выполняй эту сверку отдельно для каждого счёта.
3. Передавай `nm_abn`, `id_kng` (`ID_KNG`) и `schema` (`SCHEMA`) в GET `/pgu2/counters/api/mes/getSchetch` и `/pgu2/counters/api/mes/getLastPok`. Сверяй номер прибора по профилю и `getSchetch.result.SH_ZNK`, а даты и значения последних учтённых показаний бери из `getLastPok.result.DT_OBRZ` и `POK_T1`, `POK_T2`, `POK_T3`. Поле `SH_ZNK` в `getLastPok` не используй для сверки номера.
4. Выполни GET `/pgu2/counters/api/mes/allSchetchPok` с теми же параметрами и `dt_beg`, `dt_end` в формате `ДД.ММ.ГГГГ`. Штатная форма запрашивала три года до текущего дня включительно. Для текущей сводки сформируй этот диапазон по московской дате. Архив возвращает строки в `result.getDataReturn`. Сопоставляй `SH_NUM` с номером прибора, если поле присутствует. `DT_OBRZ` — дата записи, `NM_T1`–`NM_T3` — названия тарифов, `VL_T1`–`VL_T3` — их значения. Сортируй по дате, используй тарифы выбранного прибора и сохраняй числовой ноль. Сверь последнюю учтённую запись с `getLastPok`. Отсутствие записи утверждай только для успешного ответа, покрывающего нужные даты.
5. Выводи отдельно последнее учтённое показание и последнее переданное клиентом, с датой и тарифами. Источник строки бери из `NM_OBH`. В проверенной выборке запись «Переданные клиентом» имела `TP_OBH = "55"`, а «Снятые сотрудниками Мосэнергосбыт» — `TP_OBH = "6"`. При неизвестном источнике не приписывай показания клиенту. В текущем месяце отдельно отмечай, были ли показания клиента и есть ли учтённые показания из другого источника. Если API даёт только дату записи и расчётный период нельзя установить, подпиши дату и укажи, что расчётный период не подтверждён.

## Проверка при изменении портала

Сверь одну квартиру в каждом сервисе по номеру прибора, датам и показаниям. Для электричества сопоставь последнее учтённое значение с разделом «Предыдущие», а записи клиента — с таблицей «Архив показаний». Проверено, что таблица может показывать только записи клиента, хотя полный ответ API содержит также замеры сотрудников. При ином необъяснённом расхождении укажи его и используй форму для подтверждения. Цепочка от профиля до архива проверена в Edge для всех трёх сохранённых квартир.
