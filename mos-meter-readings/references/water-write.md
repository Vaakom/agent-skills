# Отдельная передача водосчётчика

Прямой PUT из Codex проверен 28 ноября 2026 года в авторизованной вкладке Edge через штатную возможность `cdp`. Запрос получил HTTP 200, повторный GET без кэша подтвердил сохранение показания выбранного прибора.

1. Используй действующую сессию `ed.mos.ru` в выбранном Edge или Chrome. При необходимости пользователь входит вручную. В «Платежи и счетчики → Водоснабжение» выбери квартиру. Получи наблюдавшийся GET `/api/efp/counters/getWaterInformation` с `userPlaceId`. В `data.counters` сверь `num` и `typeName` целевого прибора, возьми его `counterId`. Проверь `isActive`, расчётный период в форме, `transferUnavailableReason`, `hasDateTransferred` и `currentPeriodValue`. Проверь показание по правилам SKILL.md. Если текущее значение уже совпадает с запрошенным, сообщи об этом и заверши. Для другого ранее переданного значения применяй процедуру исправления только по отдельной команде.
2. При наличии поддерживаемого средства исполнения авторизованного PUT по явной команде пользователя выполни один PUT на `https://ed.mos.ru/api/efp/counters/addIndicationsList/` с `Content-Type: application/json`. Передай в теле `userPlaceId` (число), `period` (последний день расчётного месяца в формате `YYYY-MM-DD`) и `counters` (массив из одного объекта). В объекте передай `counterId` (число), `num` (строка с номером из API чтения, включая ведущие нули) и `indication` (целое число м³ по правилам формы). Обычная навигация вкладки выполняет GET, а `pageAssets` служит для просмотра ресурсов. Для PUT требуется отдельная поддерживаемая возможность, работающая в авторизованной сессии без экспорта cookies или токенов.
3. В выбранном Edge или Chrome открой раздел водоснабжения в `ed.mos.ru`. Если сеанс завершён, запусти штатный вход. При запросе учётных данных передай вход пользователю. После выбора квартиры возьми `userPlaceId` из параметра `address` открытой страницы и сверь с `data.userPlaceId` в GET. Перед записью проверь `data.enableTransfer` и расчётный месяц в карточке прибора.
4. Прочитай документацию возможности `cdp` выбранной вкладки. В пределах origin `https://ed.mos.ru` используй разрешённый `Runtime.evaluate` с `awaitPromise: true` и `returnByValue: true` для однодоменного `fetch`. Браузер сам использует действующую сессию. Для PUT используй `redirect: 'error'` и возвращай из выражения только нужные поля статуса. Если возможность недоступна, сообщи об ограничении. Переход на кнопку «Передать» в карточке выбранного прибора согласуй с пользователем, если он запросил API.
5. После попытки отправки выполни `getWaterInformation` с `cache: 'no-store'`. Сверь `currentPeriodValue`, `hasDateTransferred` и месяц по нужному `counterId`. При обрыве связи или неоднозначном ответе проверь сохранённое значение до любых дальнейших действий. Если статус остался неизвестным, остановись без повторной записи. Сообщи только подтверждённый результат.
