# Local permissions

Используй установленный локальный запускатель для уже разрешённых операций. Скилл описывает транспорт задания; правила записи встречи, чтения почты и выбора проверок остаются в соответствующем скилле или инструкции инструмента.

## Зависимость и границы

Этот скилл рассчитан на существующую Windows-инсталляцию: исходники запускателя — `C:/AI/AI Native/products/local-permissions`, Python — `C:/AI/Tools/.dion-secretary/venv/Scripts/python.exe`, очередь — `C:/AI/Tools/local-permissions`. Код запускателя не входит в этот репозиторий. При отсутствии файлов сообщи, что предпосылка недоступна; не устанавливай продукт и не переноси пути с другого компьютера автоматически. Перед новым типом задания прочитай локальный `products/local-permissions/README.md` и сверяй схему с `run.py`.

Наличие скилла, allowlist или старого успешного запуска не является разрешением пользователя. Проверяй поручение и действующие границы доступа. Запускатель не предоставляет доступ к `private`, отправку и изменение почты, публикацию, установку ПО, произвольный shell или изменение системных настроек. Не расширяй правила Python/PowerShell и не меняй sandbox ради выполнения задания.

## Проверенный запуск

Задания выполняй строго последовательно. Используй две фиксированные команды без аргументов, конвейеров, перенаправлений и дополнительных shell-выражений. Для этой инсталляции они сопоставляются с узкими сохранёнными правилами среды.

1. Запусти `submit.py` вне sandbox с `tty=true`:

   ```powershell
   & 'C:\AI\Tools\.dion-secretary\venv\Scripts\python.exe' -X utf8 -B 'C:\AI\AI Native\products\local-permissions\submit.py'
   ```

2. Дождись `Ready for one JSON request line on stdin.` Передай через `write_stdin` одну строку UTF-8 JSON и завершающий перевод строки. Примеры и поля — в [references/requests.md](references/requests.md). Не включай секреты. Дождись `state=queued` и успешного завершения процесса; если процесс ещё работает, дождись завершения перед следующим шагом.

3. Запусти вне sandbox точную команду:

   ```powershell
   & 'C:\AI\Tools\.dion-secretary\venv\Scripts\python.exe' -X utf8 -B 'C:\AI\AI Native\products\local-permissions\run.py'
   ```

4. Прочитай вывод и код завершения. Если получен идентификатор работающего процесса, продолжай ждать именно его. Код завершения submit подтверждает только постановку задания; завершение run — выполнение команды, а не автоматически достижение всей цели.

Не заменяй submit одноразовым `python -c`, shell-конвейером или ручной записью request.json. Если среда запросила техническое подтверждение, используй штатный механизм и действующие правила уведомления/журналирования. Сохранённое правило не гарантирует автоматическое одобрение в новом сеансе или на другом компьютере.

## Сбои и проверка результата

- При отказе валидации исправь только неверные поля, сверившись с текущей схемой. Не обходи ограничения запускателя прямой командой.
- При существующем задании, `processing.json` или `dispatch.lock` сначала выясни состояние собственного запуска. Не удаляй очередь и блокировки и не подавай повторно start, stop, export или open вслепую. После сбоя/тайм-аута проверь, не выполнилось ли действие, прежде чем повторять.
- После старта Dion проверь status, реальное накопление аудио и свежие события журнала выбранной встречи. Сообщи отдельно результат аудио и журнала участников; старый файл не доказывает запись имён. Не запускай аудиозапись ради тестирования скилла. При запросе расшифровки доведи обработку через `awaiting_codex` до `finalize-minutes` по инструкции Dion.
- Для почты учитывай неполный поиск, усечение тела и manifest экспорта; успешный выход не доказывает полноту. Чтение живого ящика — только по соответствующему поручению.
- Для открытия документа проверь цель до задания. Результат `open` означает запрос ОС, а не доказательство открытия нужной страницы в интерфейсе.
- Для аудита сообщай режим и текущий результат: PASS, FAIL или UNAVAILABLE. Полный аудит выбирай по README инструмента, не ради проверки транспорта.

Проверка создания этого скилла не требует записи звука, доступа к почте, открытия окон или изменения разрешений. Для инструкций достаточно валидации скилла и статического аудита; синтетические тесты продукта нужны при изменении запускателя.
