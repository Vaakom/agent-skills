## ADDED Requirements

### Requirement: Отдельная передача показания воды через API

Скилл SHALL адресовать запрос записи одному водосчётчику и одному расчётному периоду после сверки прибора и показания. В `PUT /api/efp/counters/addIndicationsList/` массив `counters` SHALL содержать ровно один элемент с идентификатором, номером и показанием выбранного прибора.

#### Scenario: У второго прибора уже есть показание

- **WHEN** пользователь поручает через API передать показание выбранного водосчётчика и в квартире есть другой прибор с принятым значением
- **THEN** скилл использует только идентификатор и значение выбранного счётчика и проверяет результат по нему

#### Scenario: Авторизованный PUT недоступен

- **WHEN** среда умеет читать данные, а поддерживаемый авторизованный PUT недоступен
- **THEN** скилл сообщает об ограничении и при согласии пользователя использует отдельную кнопку нужного прибора

#### Scenario: Прямой PUT из авторизованной вкладки Edge

- **WHEN** пользователь поручает передачу через API, портал принимает показания за выбранный месяц, а вкладка поддерживает штатный однодоменный запрос в текущей сессии
- **THEN** скилл выполняет один PUT для выбранного прибора и подтверждает результат повторным GET без кэша

#### Scenario: Результат запроса неизвестен

- **WHEN** после попытки отправки нет однозначного ответа
- **THEN** скилл проверяет показание через чтение и при неизвестном результате прекращает попытки записи
